# Coppermind: plan and status

**Last updated:** 2026-10-23 (M4 done: tool registry, schemas, path confinement)

## Current status

- **Current phase:** Phase 2, Copper can use tools
- **Current milestone:** M5, the agent loop `[jake-writes]`
- **Done so far:** Phase 1 complete (M0–M3). M4 complete: `list_files` / `read_file`, `build_registry()` with schemas and `writes` flags, confinement tests passing.
- **Next step:** Jake writes `agent.py`. Notes root still needs to come from config (e.g. `COPPER_NOTES_DIR`) when the CLI builds the registry.
- **Blockers:** None.

## Vision

A personal agent Jake uses daily, mostly from the terminal. It runs entirely on his own hardware and reaches his notes, documents, code, website, and future apps through plug-ins. It's private by default, asks before it changes anything, and is simple enough that Jake understands every part of it. Later it gets a local GUI writing workspace with Copper built in.

## Architecture

- **Interfaces:** `copper` CLI first (REPL, one-shot). GUI workspace later (Phase 4). Both are thin clients of the same agent core.
- **Agent core:** hand-written loop. Sends messages and tool schemas to the model, runs requested tools, feeds results back, repeats until the model answers. Enforces permissions and logs every tool call. Emits events that any interface can render.
- **Model server:** Ollama (or any OpenAI-compatible server) on Jake's hardware, swappable via config.
- **Memory:** search index over notes and documents (M9).
- **Integrations:** one MCP server per app (krushcomics first, then notes, code repos, future apps), each with its own permissions.

## Phase 1: Talk to Copper

**Phase 1 is complete when both of these work from any terminal:**

```
$ copper
Hi, my name is Copper. How can I help you?
> What is the capital of Spain?
The capital of Spain is Madrid.
> /quit

$ copper -p "What is the capital of Spain?"
The capital of Spain is Madrid.
```

(Inside the REPL the input prompt is `> `, not `$`, so it's obvious you're talking to Copper and not your shell.)

### M8: krushcomics publishing (first real integration)

The target flow, all from the terminal:

1. Jake: "Read my scratch notes in `~/notes/scratch/dune-3.md` and turn them into a review for the site."
2. Copper reads the notes and drafts the post (title, type post/review, body, tags).
3. Copper shows a preview in the terminal. Jake asks for changes or approves.
4. On approval, Copper publishes exactly the previewed version and returns the live URL.

Work on the **krushcomics side** (separate repo, part of the backend API project):
- [ ] Post model with `status` (draft/published) and type (post/review)
- [ ] API endpoints: create draft, get draft, publish draft
- [ ] Token scoped to posts only (no delete, no user/admin actions)

Work on the **Coppermind side**:
- [ ] krushcomics MCP server with `create_draft` and `publish_post` (both `writes=True`)
- [ ] Preview rendering in the terminal
- [ ] Approval bound to a hash of the previewed content; `publish_post` refuses if the content changed since approval
- [ ] Token loaded from `~/.config/coppermind/` or an environment variable, never the repo

**Done when:** a sandbox scratch-notes file becomes a published review on krushcomics, with Jake approving the exact content in `copper`.

## Phase 4: Coppermind workspace (GUI), not started

Inspired by Odysseus (PewDiePie's self-hosted AI workspace). A local writing workspace with Copper built in: the note-taking of Obsidian with the writing feel of Google Docs.

What Jake wants:
- Folder-based like VS Code: open any folder and work in it, not one giant vault
- No graph view
- A comfortable editor for stories and novels, CTF write-ups, code documentation, and other documents
- Copper built in, able to reference the open documents and folder, e.g. read through a story and give feedback and suggestions based on what Jake is going for
- Connections to Jake's other apps (same MCP servers as the CLI)
- Everything local: writing never leaves Jake's machines

Leaning (not decided): a local web app launched with `copper ui`, Python backend serving a browser UI bound to localhost, the same pattern Odysseus uses. Reuses the agent core and its events directly.

Design questions for when this phase starts are listed under Open questions.

## Decision log

| Date | Decision | Why |
|---|---|---|
| 2026-10-22 | Project name Coppermind; CLI command `copper`; assistant name Copper | Cosmere reference: copperminds store memories. |
| 2026-10-22 | Phase 1 goal: interactive REPL with greeting, plus one-shot prompt flag | Smallest version that's genuinely usable; proves install, model connection, and conversation. |
| 2026-10-22 | One-shot flag is `-p` / `--prompt`; `-m` reserved for `--model` (proposed, confirm) | `-m` conventionally means model in LLM CLIs; keeps room for model switching. |
| 2026-10-22 | Local only: all inference on Jake's hardware, no cloud providers by default | Jake's writing and notes must not leave his machines. |
| 2026-10-22 | Python for the core and CLI | Jake's strongest language; understanding every line while learning agent concepts outweighs Go's packaging advantages. Installable via console script + pipx. |
| 2026-10-22 | Self-hosted models behind an OpenAI-compatible endpoint, Ollama by default | Models and hardware will change, so the backend must be swappable. |
| 2026-10-22 | Hand-written agent loop, no agent frameworks | Learning goal; full understanding and control. |
| 2026-10-22 | MCP as the plug-in boundary for integrations | Future apps plug in without touching the core; servers can be in any language. |
| 2026-10-22 | CLI first; core emits events, interfaces stay thin | Fastest to build and best for debugging; the GUI reuses the same core later. |
| 2026-10-22 | krushcomics is the first integration: notes → draft → preview → approve → publish | Jake's first real use case. |
| 2026-10-22 | Publishing requires approval bound to a hash of the exact previewed content | The agent reads untrusted content, so prompt injection could alter a post between preview and publish. |
| 2026-10-22 | `httpx` for HTTP; `pytest` and `ruff` for development | Keeps the protocol visible with minimal dependencies. |
| 2026-10-23 | The notes root is bound into each tool by `build_registry()`; schemas expose only `path` | The model (or an injected note) must never choose which folder it may read. |
| 2026-10-23 | File tools refuse hidden files and skip symlinks that resolve outside the root | Notes folders often contain `.env`, `.git/`, `.obsidian/`; listing escaping symlinks leaks names. |

## Open questions

- Which machine hosts the model long term: the Acer, the new laptop, the home-lab server, or a GPU box later?
- Which model(s) to standardize on once hardware is settled.
- Where real notes live and in what format. Affects M8 and M9.
- Website preview: terminal-rendered markdown, a private draft URL on krushcomics, or both?
- Phase 4: store documents as markdown files (portable, git-friendly) or a rich-text format (closer to Google Docs)? A WYSIWYG editor over markdown may give both.
- Phase 4: local web app (`copper ui`) vs. a desktop app wrapper?
- Phase 4: novels are longer than a small local model's context window, so story feedback needs chunking or retrieval. How much model does Jake's hardware allow?
- License, if Coppermind is ever published.
